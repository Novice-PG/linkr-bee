# Agent 优化与实机验收

## 软件行为

输入快捷键：`⌘/Ctrl + Shift + K` 打开并聚焦 Agent；`⌘/Ctrl + Enter` 发送；普通 Enter 换行。中文输入法组合输入期间不会触发这些快捷键。箭头按钮保留可访问的“发送”名称，悬停可查看发送快捷键。

- **任务记录与设备**：按 BLE 设备 ID / WebSocket 地址和 UART 设置隔离，最多保存 20 个任务摘要。刷新后运行中的摘要显示为中断。点击“核实上次任务”只填入问题，提交后必须先读取当前设备状态与串口日志，下一轮才能申请新动作。不会恢复旧命令队列或授权。
- 记录仅保存目标、回答摘要及最多 8 条执行结果元数据，不保存可重发命令和模型配置。常见凭据格式及 URL 查询参数做脱敏，但自由文本仍可能包含设备信息；可以清除当前设备记录。存储失败会提示。
- **探测设备**：使用 `probe_device_profile` 读取 OS、板型、boot ID、根文件系统容量和工具路径是否存在。沿用执行档位的审批规则；成功的完整输出才生成档案。档案为当前会话内观测值，重连后清空，识别重启、日志丢失或超过 15 分钟后标为过期。串口无法可靠识别所有自定义重启输出，操作前仍需核实目标。
- **交互**：识别 sudo 密码、密码、登录、确认和分页提示；监视工具遇到等待输入立即返回。密码由用户直接在终端输入。提示识别是启发式观察，不授予自动执行权限。
- **执行记录**：显示命令、耗时、传输状态、退出码、下载元数据；日志可展开，命令与 Markdown 代码支持复制。退出码不代表最终目标验证通过。
- **上下文**：增量读取日志；旧证据压缩时保留头尾及选取的错误行，机械摘要去重；保留当前问题和合法工具调用/结果配对。不引入额外摘要模型调用。

## 2026-09-09 初期实机状态（后续结果见文末）

初期检查未发现 USB 串口设备，系统权限下扫描 BLE 8 秒也未发现名称包含 Linkr / Bee / UART 的设备。以下为验收计划，后续目标机绑定与 Agent 实机结果见文末。主机回归不替代无线通信、掉电保持或内存压力验证。

接入 Bee 后按以下顺序验收，分别记录固件版本/哈希、板型、连接方式和原始日志：

| 项目 | 操作 | 验收证据 |
| --- | --- | --- |
| 首次配对门控 | 未绑定主机在 GPIO1 高电平申请；拉低后重新申请 | 高电平拒绝新 bond；低电平成功并加密 |
| bond 持久化 | 释放 GPIO1，Bee 断电再上电，同一主机重连 | 无需重新按键，GATT 使用加密连接 |
| 新主机配对 | 第二台主机分别在 GPIO1 高/低电平申请 | 高电平拒绝；低电平可配对；保留已绑定主机行为记录 |
| 断连恢复 | 在持续 UART 输出时断开 BLE/网络并重连 | 明确日志缺口，无旧命令自动重发，重新确认会话 |
| WebDAV 持续上传 | 在可信测试端点启用日志上传，持续输入带序号的测试日志，累计至少 128 MiB；同时保持 BLE 或 WebSocket 会话 | 服务端实际文件、累计字节、序号缺口、双方 SHA-256；不能只看客户端完成提示 |
| 上传故障 | 中途关闭/恢复测试端点 | 记录丢弃/失败/成功计数，恢复后不死锁，队列受限 |
| SRAM 压力 | 在配对、WiFi、WebDAV、BLE/WebSocket 并发下采样 | 堆当前/峰值与各线程栈高水位、分配失败和复位原因；构建静态 RAM 数字不作为运行峰值 |

SRAM 高水位需要带运行时堆/线程统计的诊断构建；若当前镜像未提供统计接口，应先记录该限制，再构建并单独验收诊断固件。不要根据 C3/C5 历史构建报告推断当前硬件余量。

## AI 设置中的目标机绑定

AI 设置现在提供核实、绑定、解除和重新生成入口。通过 BLE 管理通道使用 `@linkr target?`、`@linkr target=<UUID>`、`@linkr target clear`；固件把目标 UUID 保存到 settings 的 `linkr_target/v1`，相同值不重复写入。UUID 是关联标识，不是目标机身份认证凭据。

绑定在目标机 `/var/lib/linkr/device-id` 创建 UUID，已有合法 UUID 保留；重新生成必须勾选允许替换，以临时文件加重命名更新。操作要求已登录的 POSIX Shell。优先读取已有系统 ID，其次读取用户目录 ID；首次创建优先尝试系统目录，必要时通过 sudo 提权，用户直接在串口输入密码。sudo 不可用或失败时回退到 `~/.local/share/linkr/device-id`（随登录用户变化）。已有系统文件读取失败或不合法时不另建身份。出现密码提示后本次自动核实暂停，命令结束后需再次点击绑定重新读取 ID；不采集或自动输入密码。读取普通文件、命令成功及 UUID 格式全部确认后才请求 Bee 保存。没有 Bee 成功响应、断连或日志不完整都不能视为绑定成功；目标机文件可能已写入，恢复后先核实，不自动重放。

解除只清除 Bee 关联。核实成功后任务历史改用目标 UUID 作为索引，已探测档案以历史信息保存到当前浏览器；动态状态仍需按需核实。重连取消本次核实状态，用户可用“核实绑定”读取一次 ID。旧的 Bee/地址索引历史不自动迁移，避免错误关联。

初期验证：主机设置存储桩测试与模拟 BLE/UART 浏览器测试覆盖正常及失败路径。当时尚未完成实际 Flash 写入或真实目标机绑定；后续实机结果见下文。

连接后，在本次会话观察到空闲 Shell 时自动核实一次目标身份：查询 Bee 绑定并只读取目标 ID 文件；没有绑定时不发送串口探测。只有 UUID 匹配才加载浏览器中对应的历史能力档案；登录/密码提示、ID 缺失、不匹配或输入被打断都不授权历史档案，也不自动循环探测。Agent 使用 `probe_tools` 按任务检查所需命令；完整设备探测仅用于未知目标或明确的全面调查。实时磁盘空间、网络和进程仍需按任务重新读取。

## 2026-09-10 任务执行增强

- 多步任务可调用 `update_task_plan` 保存最多 8 步的计划；同时最多一步进行中。完成步骤必须记录验证结果；受阻步骤必须记录原因和下一步。计划是 AI 的判断，不代表应用已独立验证，也不授予串口执行权限。
- 计划、验证摘要和恢复建议经过现有脱敏后保存到当前设备的任务记录；未完成计划保存为 interrupted。恢复时携带计划，但继续要求先读取当前设备状态和串口日志，禁止重放历史命令。
- `probe_tools` 成功且输出完整时，保存本会话的工具可用/缺失状态、检查时间和执行 ID；Agent 可复用未过期结果。超过 5 分钟、连接变化、启动/登录输出或日志缺失时标为 stale。安装软件、切换用户或 PATH 后仍应主动重新检查。专用下载探测规则不变。
- 主机回归 120 项通过，前端构建通过；本轮未向实机发送诊断、安装或修复命令。

### 文档与日志定位

`read_web_page` 增加 `offset` / `limit` 分页和 `find`（不区分大小写的文本查找），返回实际读取范围、总字符数、匹配位置、后续偏移与获取时间。单页仍限 512 KiB，单次输出限 16000 字符；每次重新获取网页，动态页面的偏移可能变化。CORS 限制仍如实报错，不引入下载或代理服务。

`search_serial_log` 只搜索指定日志窗口，返回最多 12 段上下文、日志范围和截断状态，不发送 UART 输入，也不移动 `read_serial_log` 的连续读取游标。无匹配仅代表当前窗口；跨窗口关键词需重叠读取，已被淘汰的日志不能恢复。

新增功能的主机回归共 123 项通过，前端构建通过；浏览器工具循环覆盖长文档后半段定位和日志错误查找。测试使用模拟网页、模型和设备，没有调用真实模型或对目标机执行命令。

### 执行中补充与后续任务队列

运行时可继续输入：“补充本轮”（或 Ctrl/Cmd+Enter）使用 Pi 的 steering 队列，在工具执行边界处理；“排队下一步”使用 follow-up 队列，等当前任务循环结束后处理。补充不强行中断已经发出的串口命令。启动完成前按钮不可用，期间输入的草稿保留。

界面显示待处理消息，支持清空全部待处理项；最多 8 条，每条最多 4000 字符。停止、异常、达到执行上限、断连或切换设备时清空队列。待处理队列不持久化；已消费消息纳入当前对话与任务目标。队列共享当前运行的轮次、工具和时间预算，不重置串口确认、设备会话校验或下载阶段限制；下载完成后的安装/刷写应在本次运行结束后另行发起。

主机回归 127 项通过，覆盖优先级、容量限制、清空、停止和预算耗尽后不重放。模拟浏览器在 390 与 1280 像素宽度验证两类排队消息的消费顺序，并检查停止与设备会话隔离。截图确认队列和输入框可见；本轮没有调用真实模型或向实机发送 UART 命令。
