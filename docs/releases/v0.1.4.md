Linkr Bee 项目级发布 **{{TAG}}**：在 v0.1.3 的基础上，补齐 Web 终端的双传输兼容、桌面终端的焦点行为、移动端基线、ESP32-CAM 固件目标和独立维护的浏览器刷机页。所有附件都由同一提交 `{{SHA}}` 构建。

`{{TAG}}` 是 fork 的项目发布标签；本次所有组件统一为 `{{FIRMWARE_VERSION}}`：固件、Rust CLI/TUI、Web/mobile 包，以及 Android 调试 APK 的原生 `versionName`。

### 本次新增

- **浏览器里直接刷固件。** 新增独立维护的 `flash.html` 刷机页：自动读取仓库最新一次发布的固件，按板型列出 BLE 固件，用 Web Serial 在桌面版 Chrome / Edge 里直接烧录，不需要安装 esptool。页面与终端共用同一套视觉风格，但不提供返回终端的入口，固件按同源方式随 GitHub Pages 一起发布。Android APK、iOS 和 HarmonyOS 包不包含刷机页和 Web Serial 库，因为原生 WebView 无法访问串口。

- **新增 ESP32-CAM 固件目标。** ESP32-CAM 使用经典 ESP32，烧录和桥接都走 UART0（GPIO1 TX / GPIO3 RX），不占用 CH340。相机、SD 卡和 I2C/SPI2 关闭，2 MiB PSRAM 用于 WebDAV 日志环、上传缓冲、BLE 队列和 WS 客户端栈，内部 DRAM 留给 UART RX 环和蓝牙主机。该板广播 `PREFER_NUS`，Web 端自动改用 NUS；看门狗回退延时提高到 10000。原 `esp32-wroom-32` 的 UART2 行为和产物名保持不变，新增产物为 `linkr-bee-{{FIRMWARE_VERSION}}-firmware-esp32-cam.zip`。

- **Web 终端同时支持 Reliable UART 与 NUS。** 主线和旧板型继续使用 Reliable UART；ESP32-CAM 广播 `PREFER_NUS` 能力后，Web 自动选择 NUS，并在订阅失败时回退。连接前会清理旧的 GATT 缓存，NUS 订阅优先于残留的 Reliable-UART CCC，重连后不需要手动清除浏览器蓝牙缓存。

- **桌面终端的焦点回到终端。** 从侧栏切换视图或打开内容后，`bee` 的焦点回到终端区域，键盘输入不再留在导航栏。窗口或面板尺寸变化后，空闲提示符会补发 `stty rows/cols`，保持远端 tty 与本地窗格一致。

- **移动端基线跟随 0.1.4。** 触摸选择、滚动条、软键盘与设置侧栏的行为保持 v0.1.3 的约定；测试基线、APK 版本号、iOS / HarmonyOS 版本号和 Web 关于页统一到 `0.1.4`。

### 下载选择

按主机平台从 Release 附件中选择 `linkr-bee-{{FIRMWARE_VERSION}}-<target>`；Windows 提供 MSVC 与 GNU 两套 ABI，macOS 提供 Apple Silicon 与 Intel。只使用终端时可下载 `linkr-bee-cli`。

### 刷写与校验

每个固件 ZIP 都带 `firmware.json`、`SHA256SUMS` 和对应板型的 `FLASHING.txt`。刷机页会校验镜像大小与来源；命令行刷写可参考 ZIP 内的说明。刷机默认不擦除设置分区。

### 平台说明与验证范围

Web 刷机需要安全上下文（HTTPS 或 localhost）和支持 Web Serial 的浏览器。GitHub Pages 提供 HTTPS；局域网自建页面请使用 `localhost`，或按浏览器要求配置证书。BLE 需要安全上下文和支持 Web Bluetooth 的浏览器；局域网 WebSocket 桥接在 HTTPS 页面下可能显示混合内容警告。
